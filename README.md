# Извлечение разделов из протоколов

Скрипт `extract_sections.py` извлекает разделы `Описание` и `Заключение` из
DOCX-файлов. Он использует только стандартную библиотеку Python и ищет файлы
рекурсивно, если передана папка.

```bash
# Обработать все DOCX в папке «условия» и вывести JSON в терминал
python extract_sections.py

# Сохранить результат в файл
python extract_sections.py условия -o sections.json

# Обработать один документ
python extract_sections.py "условия/протокол.docx"
```

Для каждого документа в JSON создаётся объект с путём к исходному файлу и
полями `description` и `conclusion`. Если раздел не найден, его значение —
`null`. Ошибки чтения отдельных файлов выводятся в stderr; остальные документы
при этом продолжают обрабатываться.

## Разбор описания с Natasha

Установите зависимость проекта командой `uv sync`.

Для backend можно использовать `ClinicalDescriptionParser` из
`sparrow.backend.parsers.clinical_parser`. Экземпляр парсера следует создать
один раз при старте сервиса и переиспользовать: инициализация Natasha загружает
языковые модели. `parse()` возвращает фрагменты описания с исходным текстом,
леммами, статусом (`норма`, `изменение`, `патология`) и срочностью (`норма`,
`планово`, `срочно`, `неотложно`).

```python
from sparrow.backend.parsers.clinical_parser import ClinicalDescriptionParser

parser = ClinicalDescriptionParser(
    urgency_rules={
        "неотложно": ["немедленная госпитализация"],
        "срочно": ["срочная консультация"],
    }
)

result = parser.parse(
    "Артерия проходима. Выявлена киста; рекомендована срочная консультация."
)
```

Словари срочности дополняют встроенные правила; допустимые категории:
`норма`, `планово`, `срочно`, `неотложно`. Категории статуса определяются
эвристическими словарными правилами; фрагмент без совпадений получает статус
`изменение` с правилом `описанный_фрагмент_без_совпадения_с_правилами`.
Неуказанная срочность для нормального фрагмента считается `норма`, для
остальных — `планово`. Это извлечение текста, а не диагноз или медицинская
оценка срочности; правила нужно адаптировать и проверять на данных сервиса.
Числовые измерения не сравниваются с референсными диапазонами автоматически:
указание диапазона «норма» само по себе не делает измерение нормальным.

## FastAPI

Установите зависимости проекта командой `uv sync`, затем запустите сервис:

```bash
uv run uvicorn sparrow.backend.api:app --host 127.0.0.1 --port 8000
```

`POST /extract` принимает JSON с полем `text` и возвращает найденные фрагменты:

```bash
curl -X POST http://127.0.0.1:8000/extract \
  -H 'Content-Type: application/json' \
  -d '{"text":"Артерия проходима. Выявлена киста."}'
```

В ответе каждый элемент `findings` содержит исходный фрагмент как `summary`,
его статус и срочность. Леммы и внутренние правила классификации клиенту не
возвращаются. Поле
`structured_data` отдельно содержит служебную информацию и структуру органов,
например:

```json
{
  "служебная_информация": {
    "тип_исследования": "УЛЬТРАЗВУКОВОЕ ИССЛЕДОВАНИЕ ОРГАНОВ МАЛОГО ТАЗА",
    "аппарат": "SIEMENS ACUSON REDWOOD"
  },
  "структуры": {
    "матка": {
      "положение": "anteflexio",
      "размеры": "72х59х64 мм",
      "контуры": "ровные",
      "наблюдения": ["Достоверно узловых образований не определяется"]
    },
    "правый_яичник": {
      "размеры": "24х13х16 мм",
      "образования": [
        "Праровариально лоцируется ... 12х11мм (киста)"
      ]
    }
  },
  "стороны": {
    "справа": {
      "наблюдения": ["Артерии осмотрены, проходимы"],
      "сосуды": {
        "ОБА": {
          "измерения": {
            "Vps": {
              "значение": "87 см/сек",
              "референс": "норма 55-103, 90-145"
            }
          }
        }
      }
    }
  },
  "прочие_находки": [],
  "заключение": "УЗ-признаки ...",
  "рекомендации": "консультация гинеколога"
}
```

Значения берутся буквально из текста. Любой заголовок анатомического блока
(например, `ПЕЧЕНЬ`, `МОЧЕВОЙ ПУЗЫРЬ`, `ПРАВЫЙ ЯИЧНИК`) становится динамическим
ключом в `структуры`; словарь не ограничен заранее заданным перечнем органов.
Подписи `Описание`, `Заключение` и тип исследования не считаются находками:
заголовок фрагмента пропускается, тип и аппарат сохраняются в служебной
информации, а клинический классификатор получает только текстовые наблюдения.
Неназванные атрибуты остаются в `наблюдениях`, а образования — в
`образованиях`. Сосудистые измерения распознаются Yargy и группируются в
`стороны -> сосуды -> измерения`, сохраняя отдельно значения и указанные в
тексте референсные диапазоны. Отсутствующие значения не додумываются. Пустой
текст, неизвестные поля и описания длиннее 100 000 символов отклоняются с
HTTP 422.
Интерактивная документация API доступна по адресу `/docs`.
